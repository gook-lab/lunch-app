# lunch-app — 사내 점심 결정 도구

게임 여섯 가지(돌림판·사다리·슬롯·핀볼·카드·토너먼트) 중 하나로 점심을 정하고, 최근 2주에 간 곳을 빼 주는 사내용 웹앱. 로그인 없이 링크 하나로 쓴다.

설계와 구조 결정은 `~/.gstack/projects/toy/kyb-ontact-unknown-design-20260916-141116.md` 에 있다. 이 README 는 돌리는 법만 적는다.

## 스택 — 선택과 이유

| 선택 | 이유 |
|---|---|
| Vite + React + TS | 정적 SPA 하나로 끝난다. 서버가 없다 |
| Firebase Firestore | 공유 저장소가 필요한데 서버를 세울 이유가 없다 |
| Firebase 익명 로그인 | 화면에 로그인이 없으면서 규칙이 `request.auth` 를 쓸 수 있다 |
| MODUL `@gook-lab/ui` | 버튼·시트·모달·태그를 새로 만들지 않는다. 새로 만든 UI 는 게임판·로드맵·지도 핀뿐 |
| 카카오맵 JS SDK | 좌표·키워드 검색. REST 키는 쓰지 않는다 |

## 처음 돌릴 때

```bash
pnpm install          # npm 은 안 된다 — MODUL peer 의 workspace:* 를 pnpm 만 푼다
cp .env.example .env.local
# .env.local 을 채운다 (아래)
pnpm dev
```

### 환경변수

| 키 | 어디서 | 없으면 |
|---|---|---|
| `VITE_KAKAO_JS_KEY` | 카카오 개발자 콘솔 > 앱 > 플랫폼 키 > JavaScript | 지도 탭만 오류 상태가 된다. 로드맵·목록은 정상 |
| `VITE_FIREBASE_*` | Firebase 콘솔 > 프로젝트 설정 > 웹 앱 | 앱이 아예 안 뜬다 |
| `VITE_OFFICE_LAT` / `VITE_OFFICE_LNG` | 사무실 실제 좌표 | 도보시간 계산이 던진다 |

사무실 좌표는 코드에 지어내 박지 않았다. 실제 값을 넣어야 한다. 지도 탭의 회사 위치 카드로 정하면 Firestore `settings/office` 한 문서에 저장되고, 이 값이 env 보다 앞선다. 가게 도보시간은 읽을 때 지금 회사 위치 기준으로 다시 계산한다.

### 카카오 도메인 등록

플랫폼 웹 도메인에 **프로덕션 도메인 1개 + `http://localhost:5173`** 만 등록한다.
와일드카드 서브도메인은 비즈 앱에서만 되고 도메인은 최대 9개라, Vercel PR 프리뷰 URL은 사전 등록이 불가능하다. 그래서 **PR 프리뷰 배포를 쓰지 않는다.**

등록하지 않은 origin 에서는 SDK 스크립트 자체가 401 로 떨어진다.

```
{"errorType":"AccessDeniedError","message":"domain mismatched! caller=http://localhost:5173. check out registered web domains."}
```

지도 탭이 이 원인을 화면에 그대로 적어 준다. 개발 서버 포트를 바꾸면 그 포트도 등록해야 한다.

## 구조에서 알아둘 것

### 날짜 기준 — KST 고정 · 앱과 규칙 두 구현

`visits` 문서 id 가 `YYYYMMDD` 다. 기기 시계를 따라가면 노트북을 UTC 로 둔 사람이 오전 9시에 "어제" 문서를 열고, 같은 날 문서가 두 개 생긴다.

클라이언트는 `src/lib/date.ts` 의 `todayKST()`, 규칙은 `firestore.rules` 의 `isTodayKST()` 다. **규칙은 이 JS 를 쓸 수 없다** — 규칙 언어에 타임존 변환도 zero-pad 포맷도 없고 `request.time.year()` 는 항상 UTC다. 구현은 둘, 계약은 하나이고, 그 계약을 지키는 것은 `pnpm test:rules` 다.

### 후보 산출 — 순수 모듈 단일 경로

`src/lib/candidates.ts` 의 `selectCandidates()` 가 순수 함수로 정한다. 돌림판은 넘겨받은 당첨 index 로 회전만 한다. 반환은 **단계별 카운트**다 — `afterCategoryCount` 가 "N곳 중", `recentlyVisitedCount` 가 "M곳은 최근에 갔습니다". 이 둘을 헷갈리면 화면 숫자가 실제와 어긋나는데, 그 문구가 이 앱의 유일한 공정성 장치다.

### onSnapshot 순서 — 익명 로그인 완료 후 구독

`onSnapshot` 의 `permission-denied` 는 재시도 없이 리스너를 영구 종료시킨다. 익명 로그인이 붙기 전에 구독하면 **신규 기기에서만** 조용히 실패하고, 캐시된 uid 가 있는 기존 기기에서는 재현되지 않는다. `src/services/lunch.ts` 의 `subscribeToday()` 가 `authReady` 를 기다리는 이유다.

탭을 켜둔 채 자정을 넘기는 경우도 같은 급의 문제라, `useTodayKST()` 가 `visibilitychange`·`focus`·1분 타이머로 날짜를 다시 잰다.

### 규칙의 한계 — 집계·문서 수 상한 미지원

**문서 수 상한은 구현하지 않았다.** Firestore 규칙에는 집계·카운트가 없다. 막았다고 적어두면 아무도 다시 보지 않으므로, 못 한다고 적어 둔다. 8명 사내 링크에서는 목록이 이상하게 불어나면 사람이 바로 보고, 삭제 금지가 복구를 보장한다.

`auth != null` 은 "링크를 아는 누구나" 와 동치다. 접근 통제가 아니라 기기당 신원을 만들어 필드 검사를 가능하게 하는 장치다.

### places 수명주기 — 삭제 금지 · 수정과 active 토글

`visits` 가 `placeId` 를 참조하므로 삭제는 막혀 있다. 대신 `name`·`lat`·`lng`·`walkMin`·`category` 수정을 연다. 잠가 두면 좌표를 잘못 고른 가게가 `walkMin` 탓에 영원히 후보에서 빠지고, 고칠 길이 없어 풀 크기가 오염된다.

좌표를 고치면 `walkMin` 을 같이 재계산해서 쓴다. 따로 두면 둘이 어긋난다. 카테고리는 넣을 때도 고칠 때도 같은 칩(`CATEGORIES`)으로만 고른다. 글자로 받으면 목록에 없는 카테고리가 들어가 로드맵 조각과 필터에서 빠진다.

### 화면 구성 — 오늘 · 목록 · 지도 세 탭

휴대폰은 하단 탭 바, 960px 부터는 머리말 안의 탭 묶음이다.

- **오늘**: 게임 무대가 먼저, 조건(로드맵)이 아래(데스크톱은 오른쪽)에 온다. 게임이 끝나면 결과 티켓이 모달로 뜨고, 닫으면 같은 카드가 게임 아래에 남는다. 티켓 머리말은 "🎱 핀볼로 뽑은 오늘의 점심" 처럼 방금 한 게임을 적는다. 결정한 뒤와 "오늘 정한 곳" 배너에는 "동료에게 알리기" 가 있다(휴대폰 공유 시트, 아니면 클립보드).
- **목록**: 맨 위에 최근 다녀온 곳 5번, 그 아래 후보에 들어가는 가게와 접힌 "꺼 둔 가게". 줄마다 "지도" 단추가 지도 탭을 그 핀을 고른 채로 연다.
- **지도**: 회사 위치 카드(GPS · 지도 찍기 · 지도 가운데로), 가게 검색, 지도. 데스크톱은 지도 | 오른쪽 칸 두 칸이다.

로드맵은 반지름이 도보시간, 각도가 카테고리인 그림이고, 링과 조각이 그대로 필터 컨트롤이다. 실제 위경도가 아니다 — 이 그림이 답할 질문은 "어디 있나" 가 아니라 "지금 필터에서 무엇이 후보이고 무엇이 왜 빠졌나" 다. 진짜 좌표는 지도 탭이 맡는다.

점은 다섯 처지로 그린다. **후보 / 다시 넣음 / 최근 제외 / 조건 밖 / 꺼짐**. 특히 "다시 넣음"(released)을 후보와 구분해서 그린다. 최소 5곳을 채우려고 최근 방문을 도로 꺼낸 것이라, 그냥 후보로 그리면 화면이 "최근 2주 제외" 를 지킨 것처럼 보인다. 이 앱이 내세우는 공정성 장치가 그 한 가지뿐이다.

반지름은 제곱근 눈금이다(0분 32 → 15분 150, 5분 링이 100). 점심 가게는 대부분 5분 안이라 직선 눈금에선 사무실 앞에 점과 이름이 몰렸다. 같은 조각 안에서는 이름이 붙는 점(후보·다시 넣음·최근 제외)끼리 각도를 최대한 벌리고, 이름표는 아래 → 위 → 오른쪽 → 왼쪽 순으로 "사무실" 글자·링 알약·다른 이름표를 피해 자리를 찾는다. 범례는 이름이 붙는 세 처지만 적는다.

### 게임 6종 — 연출만 다르고 결과는 하나

`winnerIndex` 는 호출하는 쪽(`App.tsx` 의 `spin()`)이 `selectCandidates` + 균등 난수로 먼저 정한다. 게임은 그 결과를 보여주기만 한다. 게임이 결과를 계산하면 "최근 2주 제외" 의 공정성 근거가 무너지고 `selectCandidates` 의 테스트가 의미를 잃는다.

연출이 정해진 결과에 도달하는 방법은 셋으로 갈린다.

- **가린 칸에 놓기** (사다리·카드): 사용자가 고른 출발점·카드가 닿는 칸에 당첨을 놓고 나머지를 섞어 연다(`revealSlots`). 칸은 열릴 때까지 전부 가려져 있으므로 미리 섞어 숨긴 것과 확률이 같다.
- **이기는 대진표 만들기** (토너먼트): 당첨이 모든 경기를 이기도록 대진을 짜고, 대진 순서와 다른 경기 결과만 섞는다(`lib/tournament.ts`). 시작 전 "응원" 은 결과와 무관하다.
- **이름표 맞바꾸기** (핀볼): 물리를 한 번 실제로 돌리고, 1등한 구슬과 당첨 구슬의 이름표를 맞바꾼다(`raceForWinner`). 구슬은 이름 말고 다른 점이 없어 맞바꾼 경기도 물리적으로 맞다. 예전엔 당첨이 이기는 시드를 찾을 때까지 경기를 돌렸는데, 판을 1840px 로 늘리자 후보 20곳에서 최악 7.9초 출발 게이트가 멈췄다.

물리를 그냥 쓰면 안 되는 이유가 있다 — 구슬 레이스는 출발 위치와 판 모양 때문에 균등하지 않다. 핀을 한쪽으로만 엇갈리게 깔았을 때 오른쪽 끝 구슬이 600 시드 중 한 번도 못 이겼다. 지금 코스는 벽도 핀도 좌우 대칭이고, 대칭이 깨지면 테스트가 잡는다.

핀볼은 긴 판(1840px, 1등 도착 평균 12~14초)을 카메라가 선두를 따라 내려간다. 공이나 오른쪽 순위판 이름을 누르면 카메라가 그 공을 따라가고(스포트라이트·머리 위 이름표·실시간 등수 배지), 그 공이 들어오면 몇 등인지 알려 준다. 배속은 `lib/pinballTiming.ts` 의 연속 곡선이다 — 계단으로 바꾸면 "지연되다 갑자기 빨라짐" 으로 보인다.

모든 게임에 "크게 보기"(`.stage--full`)가 있다. 핀볼은 이때 보이는 판 높이를 줄여 가까이 당겨 보여 준다.

짧은 게임도 끝나기 직전에 뜸을 들인다. 사다리는 경로 마지막 20% 를 시간 35% 동안 천천히 내려가고(`ladderPace`, 끝은 1 이라 도착 칸 불변), 슬롯은 감속 꼬리를 길게 끌며 데스크톱에선 다섯 줄을 보여 준다. 카드는 섞은 뒤 고른 카드가 떠올라 떨리다가 뒤집히고, 토너먼트는 경기 승자가 튀어나온다.

CSS 연출은 `@media (prefers-reduced-motion)` 대신 `html[data-motion='reduced']` 를 따른다. 기기 설정이 "동작 줄이기" 여도 앱에서 "연출 켜기" 를 누르면 JS 연출과 CSS 연출이 같이 켜져야 해서다.

### 지도 탭 — SDK 동적 로드 · 라벨 핀 · 길게 눌러 가게 넣기

SDK 는 지도 탭에 처음 들어갈 때만 받는다. 결정 화면 번들에 카카오가 들어가지 않는 것은 `pnpm build` 로 확인한다(메인 번들에 `dapi.kakao` 0건).

성공이든 실패든 탭 진입당 스크립트 요청은 1회다. 실패도 캐시하고 "다시 시도" 를 눌렀을 때만 지운다 — 처음에는 실패한 약속만 버렸더니 탭을 오갈 때마다 401 이 새로 났다.

가게는 카카오 기본 마커 대신 카테고리 그림·이름·도보 분이 적힌 HTML 핀(`map/pin.ts`)으로 그린다. 이름은 `textContent` 로만 넣는다. 고른 핀은 반전되고 맨 위로, 오늘 정한 곳엔 별, 멀리 보면(배율 5 초과) 이름을 접는다. 꺼 둔 가게 핀은 기본으로 숨기고 체크박스로 켠다. 지도 위 카테고리 칩은 핀만 거른다 — 오늘 탭의 조건과는 따로다. 도보 원(5·10·15분)은 위쪽 끝에 "도보 N분" 라벨을 단다. 정해 둔 회사 위치 카드는 한 줄로 접혀 있고, "바꾸기" 로 펼쳤다가 "접기" 로 닫는다.

지도를 **500ms 꾹 누르면** 그 자리에 핀이 꽂히고 저장 폼이 열린다. 폼은 모달이 아니라 오른쪽 칸(휴대폰은 지도 아래)에 붙는다 — 모달은 방금 찍은 자리를 가렸다. 10px 넘게 움직이면 지도를 끄는 것으로 보고 취소한다. 이렇게 넣은 가게는 `kakaoPlaceId` 가 비어 있어서, 검색으로 넣은 가게와 중복 판정 방식이 다르다 — 이름이 같고 30m 안이면 같은 가게로 본다.

`map.relayout()` 을 `ResizeObserver` 로 계속 건다. 카카오는 만들 때의 컨테이너 크기를 기억해서, 그 뒤 폭이 바뀌면 타일이 예전 크기만큼만 깔린다.

## 도보시간 — 직선거리 기반 추정과 교체 트리거

직선거리 × 1.3 ÷ 67m/분. 교체 트리거는 **시드 12곳 중 2곳 이상에서 실제 도보시간과 2분 넘게 차이** 이고, 판단은 직접 걸어보고 한다. 그때 카카오 길찾기로 바꾼다.

## 판정 기준 — 2주차 visits 8건

가동 2주차 끝에 누적 `visits` 가 8건 이상이면 계속, 3~7건이면 보류(3주차 단독 3건으로 재판정), 2건 이하면 중단한다. 풀은 2주 안에 20곳을 넘겨야 최근 방문 제외가 자동 완화 없이 돌아간다.
