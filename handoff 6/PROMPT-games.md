# lunch-app 구현 요청 — 게임 3종 추가 (뽑기 기계 · 플링코 · 주사위)

시안: `design/Lunch App v2.dc.html` 의 4a·4b 방식 바 맨 뒤 세 칸. `design/LunchGame.dc.html` 의 `gacha` / `plinko` / `dice` 블록이 연출 참고용입니다.
기존 7종과 같은 규칙으로 `src/components/games/` 에 추가해 주세요.

## 공통 (기존 원칙 그대로)
- `GameProps` 를 받고 `winnerIndex` 를 보여 주기만 합니다. 게임이 결과를 계산하지 않습니다.
- `run` 이 바뀌면 새 판. 연출이 끝나면 `onSpinEnd()`.
- `prefersReducedMotion()` 이면 연출 없이 최종 장면만 그리고 바로 `onSpinEnd()`.
- 색은 게임 영역 안에서만, `categoryHue()` 틴트와 MODUL 토큰. 새 hex 리터럴 금지.
- 당첨 칸·연출 길이는 `SPIN_MS` 에 등록(핀볼·짝 맞추기처럼 가변이면 제외).
- `GAME_MODES` 와 `MODE_ICON` 에 추가:
  - `{ id: 'gacha', label: '뽑기 기계', action: '손잡이 돌리기' }` 🎁
  - `{ id: 'plinko', label: '플링코', action: '공 떨어뜨리기' }` 🔻
  - `{ id: 'dice', label: '주사위', action: '주사위 굴리기' }` 🎲
- 결과 티켓 머리말은 자동으로 "🎁 뽑기 기계로 뽑은 오늘의 점심" 처럼 붙습니다(`withJosa`).
- 테스트: 모든 `winnerIndex` 에 대해 연출이 그 칸에 도착하는지(플링코 경로, 주사위 눈 합), 후보 1·5·20곳에서 그림이 안 깨지는지.

## 1. 뽑기 기계 `Gacha.tsx` (약 2.7초)
- 돔 안에 후보 수만큼 캡슐(카테고리 색 반쪽 + 흰 반쪽). 손잡이가 360도 돌며 2.2초 동안 캡슐이 흔들립니다(180ms 간격 랜덤 오프셋).
- 흔들림이 멈추면 출구 구멍에 캡슐 하나가 떨어지고(`rise` 300ms), 0.5초 뒤 캡슐이 열리며 가게 칩(아이콘·이름·카테고리·도보)이 나타납니다. 그 캡슐이 `winnerIndex` 입니다 — 돔 안 캡슐은 서로 구별되지 않으므로 어느 것이 떨어지든 공정합니다.
- 캡슐이 20개를 넘으면 돔 안에 다 못 넣습니다. 20개까지만 그리고 나머지는 "…외 N개" 로 적습니다.

## 2. 플링코 `Plinko.tsx` (약 170ms × 후보 수)
- 핀볼(구슬 레이스)과 다릅니다. 공 하나, 삼각형 핀(행 수 = 후보 수 − 1), 아래에 후보 수만큼 칸.
- 경로 역산: 오른쪽 이동 횟수가 `winnerIndex` 가 되도록 좌/우 배열을 만들고 섞습니다(`lib/plinko.ts`, 순수 함수 + 테스트). 공은 핀마다 작게 튀며(sin 곡선 6px) 내려가고 부딪힌 핀은 강조색으로 커집니다.
- 도착 칸은 `accent-100` 바탕에 이름을 강조. 칸 이름은 세로쓰기, 위 막대는 카테고리 틴트.
- 밝은 판입니다(핀볼은 어두운 판). 게임판 바닥을 어둡게 까는 `:has(> .pinball)` 규칙은 적용하지 않습니다.

## 3. 주사위 `Dice.tsx` (가변, 보통 3~6초)
- 가게가 보드 둘레 칸이 됩니다(한 변 = ⌈n/4⌉+1, 1번부터 시계 방향). 가운데에 주사위와 상태 글.
- 말은 지난 판의 자리에서 출발합니다(없으면 1번). `winnerIndex` 까지의 거리를 1~6 눈 몇 번으로 나누되 마지막 눈이 정확히 도착하도록 `lib/dice.ts` 가 계산합니다(거리 0 이면 한 바퀴 n칸). 눈은 사람이 보기에 자연스럽게 1~6 범위 안의 난수로 채웁니다.
- 굴림마다 주사위가 회전(500ms)하고 0.55초 뒤 말이 180ms 간격으로 한 칸씩 이동합니다. 굴림 사이 0.45초. 가운데 글: "2번째 굴림 · 4".
- 도착 칸은 `accent` 테두리 + `accent-100` 바탕. 후보가 20곳이면 한 변 6칸이라 칸 이름은 말줄임 처리됩니다 — 아이콘과 번호를 먼저 보여 주세요.
- 연출이 길 수 있으니 핀볼처럼 `SPIN_MS` 에 넣지 말고 컴포넌트가 길이를 정합니다. 30초 상한 안에 들도록 최대 굴림 수는 6으로 제한(거리가 36을 넘으면 큰 눈을 우선).
