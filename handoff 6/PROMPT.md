# lunch-app 구현 요청 — 로드맵 결정 화면 · 핀볼 · 지도 마커 저장

`design/` 폴더의 HTML 시안을 기준으로 lunch-app(React + Vite + Firebase)에 아래 기능을 구현해 주세요.
시안은 브라우저에서 `design/점심 로드맵.dc.html`을 열면 동작합니다. 시안 코드는 참고용이며, 그대로 옮기지 말고 기존 구조(`src/lib`, `src/components/games`)와 MODUL 토큰(`@gook-lab/tokens`, `@gook-lab/ui`)으로 다시 작성해 주세요. 새 hex·px 리터럴은 만들지 않습니다(App.css 규칙).

## 지켜야 할 원칙 (기존 그대로)
- 당첨은 호출하는 쪽이 먼저 정하고(`winnerIndex`), 게임은 연출만 합니다. 게임이 결과를 바꾸면 안 됩니다.
- 후보 산출은 `lib/candidates.ts`의 `selectCandidates()` 하나만 씁니다. 로드맵 화면은 이 결과를 시각화할 뿐 별도 필터 로직을 두지 않습니다.
- 안내 문구는 `lib/messages.ts`를 씁니다. 숫자가 틀리면 안 됩니다.
- 가게는 삭제하지 않습니다(visits가 placeId를 참조). 수정과 끄기만 제공합니다.
- 방문 기록은 "여기로 결정"을 눌렀을 때만 남깁니다.
- 결정 화면은 스크롤 없이 게임 실행 버튼까지 닿아야 하고, 지도 SDK는 결정 화면에서 로드하지 않습니다(D7).
- `prefers-reduced-motion`이면 연출 없이 바로 결과를 보여 줍니다.

## 1. 결정 화면 → 로드맵 중심으로 재구성
탭: `로드맵 | 목록 | 지도`. 시안에 세 가지 안이 있습니다. **하나를 골라 구현** (확정 전이면 1a로 진행).
- **1a 도보권 지도**: 사무실을 가운데 두고 5·10·15분 링과 카테고리 6조각을 그립니다. 링을 누르면 도보 범위가, 조각을 누르면 카테고리(복수)가 바뀝니다. 가게 점은 상태별로 다르게 그립니다: 후보, 최근 갔지만 다시 넣음(released), 최근 2주 제외, 범위 밖, 꺼짐. 좌표는 실제 위경도가 아니라 도보시간(반지름)과 카테고리(각도)로 배치합니다.
- **1b 점심 여정 보드**: 가게를 도보시간 순으로 4×4 둘레 12칸에 놓고, 가운데에 후보 수를 표시합니다. 결과가 나오면 말이 1칸부터 당첨 칸까지 150ms 간격으로 이동합니다. 필터는 기존 칩을 씁니다.
- **1c 갈래길**: 출발 → ① 도보(5/10/15분) → ② 카테고리(복수) → ③ 최근 2주 제외 여부 → 도착(후보 목록). 각 선택지에 "그걸 고르면 남는 곳 수"를 표시합니다(`afterWalkCount`, `afterCategoryCount` 등 기존 필드 활용).
- 로드맵 아래에 게임 칩(돌림판·사다리·슬롯·핀볼)과 게임 영역, 결과 카드를 둡니다. 결과 카드에는 카테고리 배지를 붙이고, 버튼 문구는 "다시 하기"로 합니다.
- 게임 영역만 카테고리별 색(oklch 틴트)을 씁니다. 나머지 UI는 기존처럼 흑백을 유지합니다. 색은 MODUL 토큰으로 대응해 주세요.

## 2. 핀볼 게임 추가 (`components/games/Pinball.tsx`)
`GameProps`를 그대로 받습니다. 시안의 `LunchGame.dc.html` pinball 모드를 참고하세요.
- 핀 삼각형(행 수 = 후보 수 − 1), 아래에 후보 수만큼 칸을 둡니다. 칸 이름은 세로쓰기로 씁니다.
- 경로는 역산합니다. 오른쪽 이동 횟수가 `winnerIndex`가 되도록 좌/우 배열을 만들고 섞어서, 공이 반드시 당첨 칸으로 떨어지게 합니다.
- 공은 핀마다 작게 튀면서 내려가고(구간당 약 200ms), 부딪힌 핀은 커지면서 빛 고리가 생깁니다.
- 양옆 범퍼 4개가 부딪힐 때마다 번갈아 번쩍이고, 오른쪽 위에 `HIT n` 카운터를 둡니다.
- 당첨 칸은 강조 표시한 뒤 `onDone()`을 부릅니다.
- `GAME_MODES`에 `{ id: 'pinball', label: '핀볼' }`을 추가합니다.

## 3. 지도 탭 (카카오맵 JS SDK, 지도 탭에서만 lazy load)
- 사무실 마커를 표시하고, 도보 5·10·15분 원을 그립니다(원 반지름은 기존 도보 산식을 역산).
- 등록된 가게를 마커로 표시합니다. 꺼진 가게는 흐리게 표시합니다. 마커를 누르면 아래에 정보 카드를 띄웁니다(이름, 카테고리 · 도보 n분 · 가격대, 별점, 한줄평, 메모).
- **길게 눌러 핀 꽂기**: 500ms 누르고 있으면 임시 핀과 저장 시트를 띄웁니다. 도보시간은 `직선거리 × 1.3 ÷ 67m/분`으로 계산하고 "추정값"이라고 표시합니다.
- **키워드 검색**: 검색창에서 카카오 키워드 검색 결과를 골라 저장합니다. 이렇게 저장한 가게에는 `kakaoPlaceId`가 붙습니다.
- **저장 시트 입력칸**: 이름(필수, 40자), 카테고리(필수, CATEGORIES), 가격대(`~1만` / `1~1.5만` / `1.5만~`, 선택), 별점(1~5, 선택), 한줄평(40자), 메모(120자). 도보 60분을 넘으면 거부합니다(PlaceList와 같은 규칙).
- **중복 경고**: `kakaoPlaceId`가 같거나, 이름이 같고 30m 안에 있으면 "이미 등록된 곳"이라고 알리고 기존 가게로 이동합니다.
- **정보 카드에서 수정과 끄기**: 목록 탭과 같은 동작입니다. 삭제는 없습니다.
- 지도에서 저장한 가게는 바로 로드맵 후보 계산에 들어갑니다(같은 `places` 컬렉션을 씁니다).

## 4. 데이터 변경
`Place`에 선택 필드를 추가합니다: `price?: '~1만' | '1~1.5만' | '1.5만~'`, `rating?: 1|2|3|4|5`, `review?: string`, `memo?: string`.
기존 문서는 이 필드 없이도 동작해야 합니다. 이름·카테고리·주소·좌표 변경 규칙에도 새 필드를 추가해 주세요.

## 5. 유지할 기존 동작
- "오늘은 이미 정했습니다" 카드와 결정 바꾸기 확인 창("바꾸기 / 그대로 두기")을 유지합니다.
- 로딩·오류·빈 화면(`loadErrorMessage`, `emptyDataMessage`)을 유지합니다.

## 완료 기준
- `npm run test`: 기존 테스트가 통과하고, 핀볼 경로 역산 테스트를 추가합니다(모든 winnerIndex에 대해 도착 칸 = winnerIndex).
- `npm run build`: 결정 화면 번들에 카카오 SDK가 들어가지 않아야 합니다.
- 에뮬레이터(`npm run seed:fixture`)로 세 화면을 모두 확인합니다.
